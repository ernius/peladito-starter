# Adopt Kubernetes for Container Orchestration

## Owner: Jhon

## Context: 

The legacy monolith ran on static EC2 instances, making scaling slow and manual. We needed automated scaling for traffic spikes.

## Decision: 

Use Amazon Elastic Kubernetes Service (EKS) to manage all microservices containers.

## Alternatives considered:

## Consequences:

- Positive: Automatic scaling and self-healing pods reduce downtime.
- Negative: High initial learning curve for the development team. Not fixed scalling costs.
